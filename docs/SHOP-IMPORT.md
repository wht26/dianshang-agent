# 真实店铺资料接入

默认没有虚构商品。通用服装问题可以直接问；本店具体款式的问题，需要实际资料。

## 1. 整理资料

`shop-template.json` 是空店铺模板，`shop.schema.json` 是结构校验规则。JSON需使用UTF-8，页面文件最多400KB、最多100个商品条目，商品ID全店唯一。字段：

| 层级 | 字段 | 内容 |
| --- | --- | --- |
| 店铺 | name | 实际店铺名 |
| 店铺 | is_demo | 真实资料填false |
| 店铺 | policies | 公开政策，文字键值对；未核实的留空 |
| 店铺 | products | 商品列表，每款单独一条 |
| 商品 | id | 小写字母/数字开头，可含下划线或短横线，最多60字符 |
| 商品 | name、aliases | 名称和可区分该款的别名 |
| 商品 | price_cents | 可选非负整数，单位分；不是实时成交价 |
| 商品 | specs | 成分、版型、颜色、各码实测值、测量方法、洗标等，文字键值对 |
| 商品 | faq | 经店铺核实的问答，文字键值对 |
| 商品 | after_sales | 这款的特殊售后说明，文字 |

例如：`specs` 中可有“尺码表”“成分”“洗护”键，但值必须填写实测或标签信息，不能将通用品类介绍当作这款事实。不要填买家姓名、订单、地址或联系方式。可以先录入一款已核实商品，再逐步补齐目录。超过100款的目录需要后续扩展检索与分页能力。

## 2. 导入并验证

展开知识库管理 → 选择真实店铺JSON → 保存店铺与商品。目录与政策完整替换，保存到本地SQLite。刷新页面并开启新对话，确认标题、商品选择列表，再测试每款的成分、尺码、洗护与售后问题；缺失的信息应说明待核验。

原有聊天和单独导入的TXT/Markdown不会随店铺JSON替换而删除。更换店铺或政策后，应核查这些资料的适用性，避免新旧资料冲突。导入前保留原JSON以便恢复。

若使用环境变量WANG_SHOP_FILE指定文件，该文件优先生效，网页导入被禁用。修改文件后重启。

## 3. 补充长文知识

把完整的商品说明和售后流程整理为UTF-8 TXT/Markdown，在页面选择店铺通用或指定商品范围导入；单份正文最多10万字，浏览器文件最多400KB，最多100份。系统自动分段与BM25索引，不是向量数据库，也不会自动爬取平台。

通用知识覆盖常见咨询，不替代真实目录、实时订单和人工核验。目前管理页与聊天页尚无权限分离，只适合本机使用；对外服务需要补充登录、管理员权限和顾客隔离。
